# 验证与验收

按实际改动选择测试。搭建授权应用时，单元测试和真实 workerd 生命周期集成均需要；仅编辑技能文档时检查结构、引用和内容即可。

## 单元与协议测试

使用虚拟 APP KEY、Secret、handle、code、token，覆盖这些可观察结果：

| 输入/场景 | 预期 |
| --- | --- |
| 正确签名入口 | 跳转授权或已有安装页面 |
| 错 appkey、非法 handle、重复任意 key | 在发起网络请求前拒绝 |
| 非数字、秒级、过旧/未来时间戳 | 拒绝；边界按规定窗口验证 |
| 参数顺序、空格、加号、Unicode、额外 key | 原文构造和签名行为确定 |
| 回调缺 code、重复 code | 拒绝且不额外请求 token/create |
| token 成功、业务错误、无效 JSON、异常字段 | 仅符合契约的响应建立授权 |
| token/订阅返回 3xx | 不跟随，不向重定向目标发送凭证 |
| 刷新 | 上游实际收到空 body，其签名等于空 body + timestamp 的 HMAC |
| Base64 Webhook、原始 body 空格/换行变化 | 正确原文通过；篡改后拒绝 |
| 错 topic/appkey/handle/operate/timestamp、超大 body | 不撤销其他店铺、不改变状态 |
| 会话未登录、过期、伪造 | 401 并按需要清 Cookie，无 token 泄漏 |
| 未知 API、错误 method | 404/405，不返回 SPA 页面 |

## 真实 workerd 集成

用 Miniflare/workerd、临时 SQLite-backed DO 和虚拟 SHOPLINE HTTP 服务或隔离 outbound service 运行真实 Worker。只在 `tests/fixtures` 暴露 inspect、阻塞控制等测试端点；fixture 可以导入被测 Worker，但测试控制端点不得进入正式应用入口或构建产物。

每次测试新建临时持久目录，显式绑定虚拟配置，不加载 `.dev.vars`，不用真实 `.wrangler/state`。服务端断言接收到的方法、URL、body、签名和请求次数。若需要 Postman HTTP 模拟且环境提供该能力，可使用，但不为本技能文档整理初始化/发布远端 workspace。

必要场景：

1. 令牌与会话落盘，销毁并重建运行时后仍可使用；首次订阅由 Alarm 异步完成。
2. 实际 Alarm 触发刷新；调用 `alarm()` 的替身测试不能单独证明调度成功。
3. 并发会话读取/刷新只发生一次受协调的 token 请求；队列失败后后续任务仍能运行。
4. token create 等待期间收到卸载，立即完成本地撤销；晚到 token 响应不恢复安装、会话或 Alarm。
5. refresh 等待期间卸载，同样不复活；订阅创建/查询等待期间卸载也遵守撤销保护。
6. 卸载重送幂等；卸载后旧 code 回调不能复活；重新授权后旧卸载事件不撤销新安装。
7. 订阅首次失败不拒绝刚完成授权；失败计划重启后仍在，后续 Alarm 恢复。
8. 刷新失败持久退避，过期会话请求不绕过退避；超时按配置取消。
9. 401/明确未安装使全部会话撤销；网络失败/5xx 保持持久安装而报告暂不可用。
10. 有界 code 摘要、会话清理和跨店隔离成立；两个不同店铺的操作不会共享凭证。
11. 消费过的 code 在卸载、重装和重启后，在其有效窗口内仍不可重放；持久安装标识不会因运行时重启重置。
12. 业务辅助接口拒绝伪造/跨店上下文和任意出站 URL；卸载后旧上下文不能发起新请求或提交本地结果，旧安装的失败响应不撤销新授权。

端口监听 `EPERM` 应单独标记为执行环境限制；不能据此判定应用失败，也不能把未运行的集成报告为通过。

## 本地运行与前端

按目标项目实际命令运行测试、lint、TypeScript/build；bindings/vars/Secret 声明变化时生成类型。启动相关、兼容日期或运行时依赖改动必须实际启动 dev server。优先复用已有服务；新启动的测试进程使用独立状态并在结束后只清理自身资源。

本地 HTTP 检查主页、`/app`、未登录 session、未签名 callback/Webhook 和未知 API，验证状态码/Content-Type，不把 200 HTML 当成 API 成功。前端开发 StrictMode 下 OAuth 只发起一次，session 401 后不显示旧店铺，临时 503 有明确的核验失败状态。

若配置或修改 Tunnel，通过用户授权的开发 HTTPS 域名验证应用可访问、`/__debug` 与 `/cdn-cgi/local` 及子路径被阻断；本机 HTTP 不能证明 Tunnel ingress 正确。

## 配置与部署准备

验证缺少字段时只报告字段名，授权请求不使用占位值访问平台；配置补齐后不需要改源码常量。使用虚拟身份验证公开配置、scope 和 API 版本一致，APP Secret 不进入浏览器 bundle。用项目实际解析器读取 JSONC，不能在允许注释的配置上无条件使用 `JSON.parse`。

本地命令在父进程设置生产环境时仍使用开发配置。生产检查拒绝复用开发身份、域名、存储或错误绑定；生产构建检查生成配置与当前目标一致；默认 deploy 拒绝含糊目标。配置检查和构建不触发远端写入。没有部署授权时在这些本地检查后交付明确部署命令；有授权并实际部署时，再记录目标和生产 HTTPS 验证，仍单列真实 SHOPLINE 联调。

## 真实 SHOPLINE 联调

使用用户指定开发应用与开发店铺，在已授权范围内完成正常入口进入、父窗口授权、干净回调跳转、Secure/Partitioned Cookie 和重新进入。安装、卸载等真实店铺操作应在用户授权范围内。

长期令牌刷新、真实生命周期 Webhook 端到端投递、重装后的旧通知、目标浏览器分区 Cookie 支持需要单独证据；虚拟上游和本地测试不能替代真实联调。
